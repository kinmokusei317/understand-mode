# Tsuzuri の修正履歴

「Tsuzuriで推敲」で開くのは本筋の写しです。履歴を残せる操作は次の2つです。

- **AIの提案を採用する**：「書く」で範囲を選び、必要なら読み手への希望を書いて推敲を依頼します。「この提案に替える」を押すと、選んだ文、採用した文、**依頼した時点**の希望を記録します。捨てた提案、空の提案、同じ文、原稿が変わって適用できなかった提案は記録しません。
- **手直しを記録する**：「書く」で直接編集し、「履歴」で修正前後を確認します。理由は任意です。「手直しを記録」を押すまで履歴には入りません。共通の先頭と末尾を除いた1範囲を表示するので、離れた箇所を直すと間の文も入ります。挿入・削除で片側に文がなければ「（なし）」です。空の原稿は記録しません。未記録のままAI提案を採用した場合、その直前までの手直しは別に取っておき、古いものから記録できます。

「履歴をJSONで書き出す」は、記録した順の配列をダウンロードします。各要素は `before`（修正前）、`after`（修正後）、`comment`（希望または理由）、`kind`（`ai` / `manual`）、`time`（採用・記録時刻、UTC）です。保留中の手直しは入りません。

下書きと履歴の保存先はこのボードを開いたタブの `sessionStorage` です。AIに送るのは選んだ抜粋と依頼時の希望だけです。履歴や手直しの理由は送りません。保存できなかったときは警告が出ます。そのページの記憶には残るので、再読み込みする前に Markdown と JSON を書き出してください。「理解を終える」で送信に成功すると下書きと履歴を消します。自分でダウンロードしたファイルは消えません。

AIの推敲時だけ、[同梱した yomiyasu の参照資料](../skill/understand/app/public/vendor/yomiyasu/README.md) の「最優先ルール: 意味の保持」を、Tsuzuri の参考資料といっしょに渡します。Web アプリがスクリプトを実行したり、外部から取得したりすることはありません。

## CLI から標準版を使う

`bash install.sh`（Claude Code）または `bash install.sh --codex`（Codex）で `understand` を新規導入すると、同じスキル置き場に公開版 `yomiyasu` 3.4.0 の全ファイルも入ります。インストーラーはコピーするだけです。CLI を開き直し、Claude Code なら `/yomiyasu`、Codex なら `$yomiyasu` と入力して文章を渡すと、Tsuzuri とは別に公式の校正手順を使えます。

すでに `yomiyasu` があれば、ファイル・ディレクトリ・リンク（リンク切れも含む）をそのまま残します。`understand` 自体がすでにある場合は、どちらにも手を加えずインストールを中止します。

確認：`node dev/test-revisions.js`（Playwright と Chromium が必要。別の場所にある Playwright は `NODE_PATH`、既存の Chromium は `UNDERSTAND_TEST_BROWSER` で指定できます）。一時フォルダの専用ボードと偽の CLI だけを使います。

インストールの確認：`bash dev/test-install-yomiyasu.sh`。一時 HOME で両方のインストール形式を試し、全ファイルの内容・実行権限が固定コミットの Git ツリーと一致することと、既存のファイルやリンクを上書きしないことを確かめます。
