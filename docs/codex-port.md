# Codex 対応の課題設定（YOK-30）

understand-mode を、Claude Code 依存から Codex でも使えるようにする移植の、**初版の範囲・成功条件・判定方法**。実装は後続 Issue が行う。ここにあるのは「何をもって移植できたと言うか」の約束だけ。

基準：understand-mode `89ebc91`、Codex CLI `0.171.0`（実機で `exec fork` / `exec resume` の継承と親履歴の不変を確認済み）、調査は YOK-29 の報告に従う。

## 初版の範囲（最小の Codex 対応）

1. **元の回答を読む**：`$understand` で本筋（直前の回答・ファイル・diff・依頼文）を開く。
2. **文脈を引き継いだ付箋に質問する**：親の会話を `fork` で分岐し、親には書き戻さない。同じ付箋の続きだけその子に `resume` で積む。子付箋は付箋の子から分岐する。
3. **選んだ文だけ本筋へ返す**：「理解を終える」で `return.md` に利用者の文をそのまま書き、サーバーが作った子だけを後片付けして終わる。

範囲外：

- **SQLは提案だけ**。Codex 経路では `/api/runsql` を直接呼ばれても実行せず拒否する（ボタンを隠すだけではない）。
- Devin / T3Code は資料上の見通しまで。初版の対象は Codex CLI。
- 親の権限・モデルを勝手に変えない。モデル指定は `-m` を用意してよいが、未指定なら環境の既定に任せる。

## 利用者から見た成功条件

| 条件 | 判定 |
| --- | --- |
| `$understand` で意図した本筋が開く | 実機ゲート A |
| 付箋が親の文脈を知り、続き・子付箋・兄弟を混同しない | モック T1〜T4 ＋ 実機ゲート B |
| 親の会話履歴が一切変わらない | モック T4・T9 ＋ 実機ゲート B |
| 質問・下書きで勝手に実行しない（権限を拡大しない） | モック T6・T8 ＋ 実機ゲート C |
| SQL は Codex では提案だけ。直接の `/api/runsql` も拒否 | モック T7 |
| 選んだ文だけが `return.md` に戻る | モック T9 |
| 終了時に、自分が作った子だけが消え、親と無関係な会話は残る | モック T9 ＋ 実機ゲート D |
| 既存の Claude 経路がそのまま動く | `npm run test:sql`（回帰） |
| fork 非対応の Codex ・ID 不整合・中断・失敗を安全に知らせる | モック T5 |

## サーバーとの契約（モックが判定できる範囲）

テスト（`dev/test-codex-contract.js`）は実装の内部を固定しない。観測するのは HTTP の応答・起動されたコマンドの引数・ファイルの有無だけ。実装が選ぶべき外形は次のとおり。

- 起動：`server.js` を `--agent codex`（または環境変数 `UNDERSTAND_AGENT=codex`）と `--session <CODEX_THREAD_ID>` で立てる。親の ID は明示する。`latest` や `--last` で「一番新しい会話」を推測しない。
- バックエンド差し替え：`UNDERSTAND_CODEX_BIN`（既定 `codex`）で実行ファイルを指定できる（テストが偽 codex を差し込む口）。
- 付箋の初回：`codex exec --json fork <親ID>` 相当を呼び、`thread.started` の ID をその付箋の子として返す。
- 続き：同じ付箋への追問は `codex exec --json resume <その付箋の子ID>`。返ってきた ID が頼んだ子と違えば成功にしない。
- JSONL の失敗（終了コード非0・壊れた出力・`turn` 失敗・中断）は `ok:false` で返し、親も他の枝も変更しない。
- 質問・下書きでは権限を広げない（read-only 相当の sandbox を指定し、`--full-auto` / `--dangerously-bypass-*` / 承認昇格を付けない）。
- `/api/draft` は親を fork/resume しない新規実行（`--ephemeral` 可）。親の会話履歴は渡さない。
- Codex では `/api/runsql` はエージェントを一度も呼ばず `ok:false`。
- `/api/return` は本文をそのまま `return.md` に書き、サーバーが所有する子のセッション記録だけを消す。親と無関係な会話の記録は残す。

## モックと実機の境界

`dev/mock-codex.js` が証明するのは「サーバーが正しい枝を正しい順で呼び、失敗と拒否を守る」ことまで。`read-only` フラグが付くことは副作用ゼロの証明ではない。

実機ゲート（YOK-31 のリリース条件。使い捨て `CODEX_HOME`・空 cwd で行う）：

- **A. 起動**：`$understand` が Codex のスキルとして起動し、親ターン終了後もサーバーが生きて本筋が開く。暗黙起動しないこと。
- **B. 継承と親不変**：親だけに教えた合言葉を fork した子が正答し、`resume` が同じ子で続く。親の全履歴（正規化 JSON のハッシュ）が前後で一致。実際のファイル書込みや外部ツール実行がないこと。
- **C. 実効ツール権限**：質問・draft が shell・編集・外部 MCP 等の副作用経路を閉じていることを、隔離環境で実際に確認（MCP の認証エラーが出る環境では起動しない扱いも確認）。
- **D. 後片付け**：終了後、作成した子だけが `resume` 不能になり、親と無関係な枝は `resume` 可能のまま残る。
- **E. 費用とモデル**：`-m` 指定・未指定のそれぞれの実効モデルと課金を記録する。

実機で未検証の条件を、モックの合格で置き換えて「完成」と報告しない。

## YOK-31 の設計と検証方法

共有の Codex ストアに対して `delete` や `.jsonl` の削除は行わない。前者は生成された子孫にも及び得る一方、後者だけでは SQLite や別の記録形式を扱えない。最初の質問時に、指定 UUID の従来形式の親記録だけをボード専用ストアに複製する。そこで本物の `exec fork` / `resume` を使い、終了時にはそのストアごと片付ける。途中で失敗し、HTTP の応答に ID が載らなかった子も対象になる。対応できない記録形式は推測せず拒否する。親で質問を続けたり、別のプロバイダーに切り替えたりする代替はない。

これは親履歴のスナップショットであり、ライブ同期ではない。ボードを開いた後の親の発言を取り込む機能はない。一時コピーにも会話が含まれるため、作業フォルダは `mktemp -d` で作り、共有しない。強制終了・電源断では一時コピーが残り得る。子のプロセスには親のログインファイルをコピーせず、ユーザーの設定・MCP・プロジェクトの作業ディレクトリを引き継がない。親と同じモデル・契約・請求になるとは限らない。

| 確認する層 | 再現方法 | この結果からは言えないこと |
| --- | --- | --- |
| ボードの契約 | `node dev/test-codex-contract.js` | 本物の Codex の継承・実効権限・消去 |
| 従来の手動起動、Claude の回帰 | `node dev/test-codex.js`、`npm run test:sql` | 実アカウントでの料金 |
| CLI とストレージ | `python3 dev/test-codex-local.py`（Python 3、Codex 0.171.0）。実バイナリと一時 HOME・空 cwd を使い、Responses のみループバックの固定応答に置換する。`--model` は明示指定の検査用 | モデルの回答品質・アカウントの利用資格・請求・対話UIでの起動 |

`Test Behavior, Not Implementation` に従い、復旧で作られた枝を含む4件について、終了**前**に存在することと、終了**後**の消失・再開不可を照合する。エラー応答だけで合格にせず、指定の `fork` / `resume` に仕込みが渡った記録とタイムアウトの経過時間も検査する。`Prove It Works` の対象を分け、CLI 側ではモデルに渡った文脈、親記録のハッシュ、実行時点で登録されたツール、使い捨てファイルの編集拒否を観測する。

**ライブ環境で再確認する場合：** 空のローカルプロジェクトと使い捨ての認証済み `CODEX_HOME` を用意する。通常利用している会話や外部サービスは使わない。`$understand` で原文が表示されること、親ターン終了後も URL が開くことを確認する。親にだけ教えた合言葉を付箋、続き、子付箋、兄弟から質問し、親の履歴を前後比較する。費用は同一アカウントの使用記録と照合し、未指定と明示指定のモデルを区別する。応答に USD 金額がない場合はゼロと推定しない。

Devin / T3Code の会話 ID を Codex の UUID として流用しない。追加対応には、そのランタイムでの親特定、分岐、実効権限、後片付けの実証が別途必要になる。

### 隔離環境での観測（macOS / Codex CLI 0.171.0）

親・子・無関係な会話はすべて試験用に新規作成した。次の試験では **Codex 自体は実バイナリ、モデル応答はローカルの固定応答**。実アカウントによる推論・請求試験と区別する。

| ゲート | 観測したこと | 判定の限界 |
| --- | --- | --- |
| A 起動 | 一時 HOME にインストールし、実際の `codex exec` で `$understand` 指定時だけ Skill 本文が入った。通常の `workspace-write` サンドボックス内からのサーバー起動は `listen EPERM 127.0.0.1` で失敗した | **自動起動・ターン後の生存は不合格**。許可を広げず、本人のローカル端末から起動する手順を用意した |
| B 継承 | 実 `fork` / `resume` の送信内容で親の合言葉が初回・続き・子付箋・兄弟にあり、枝の合言葉は兄弟になく、draft にはどちらもない。親の全 rollout の SHA-256 は前後一致 | ストレージからモデル入力までの検証。ライブモデルが正答することや、親の書込み中の任意の瞬間を保証しない |
| C 権限 | 両モデルの付箋の続き・draft で実行時の `ALL_TOOLS` を照会。シェル実行ツールはなく、通常のファイル追加が read-only で拒否され、ファイルがないことを確認。有効なテスト MCP を置くと次のリクエストは推論前に拒否された | この版・この2モデル・ローカル設定での観測。`view_image` 等は利用可能で、ファイルの読取り禁止を保証するものではない。管理ポリシー・別モデルは未認定 |
| D 終了 | 作成した子・子付箋・兄弟の記録を収めた専用ストアはなくなり、共有元からその3 ID を実 `resume` しても記録なし。試験用の親と無関係な ID は同じ ID で再開できた | 正常終了時のセッション再開可否。OS の監査ログや強制終了後の消去までは保証しない |
| E モデル・費用 | 未指定は `gpt-6.2-sol`、`--model gpt-6.2-astra` は `gpt-6.2-astra` が実際の送信モデルだった。ローカルのモデルカタログにない `gpt-5.4` の場合は、CLI がメタデータ不足のエラーイベントを返し、ボードは成功扱いしなかった | 一時 HOME は `codex login status` が `Not logged in`。固定応答に料金は発生せず、**実アカウントでの利用可否・課金額は未検証** |

以上はレビュー用の結果であり、全リリース条件を満たしたという判定ではない。
