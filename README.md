# understand-mode（/understand）

Claude Code の出力を、付箋のホワイトボードで寄り道しながら理解するためのスキルです。

わからない文を選ぶと、その場に付箋が生えます。付箋の中では、メインの文脈を引き継いだ分身が答えます。メインの会話は汚れません。

![understand-mode のデモ](docs/media/demo.gif)

## できること

- 本筋（Claudeの出力・コード・未コミットの差分）の文や行を選ぶと、質問・詳しく・用語・図・データ・レビューの付箋が生えます
- コードと差分は行番号付きで表示し、選んだ行番号をClaudeに伝えます
- 説明に載るコードの抜粋には、ファイル名と実際の行番号が付きます
- 付箋の中でも会話でき、回答の文を選べば子付箋になります
- 図は Mermaid、グラフは Vega-Lite で描きます。本筋にも付箋にも入ります
- データの付箋では、SQLを「承認して実行」したときだけ実行し、結果の表・グラフ・SQLを並べて見られます。どうやってデータを取るかは、あなたの Claude がいつものやり方でやります
- Claude Code を確認なしのモード（`bypassPermissions`）で使っているときは、アプリも聞き返しません。提案されたSQLはそのまま実行されます
- 「理解を終える」で、本筋に影響ありの付箋からメインに返す文を下書きし、送ったら寄り道の記録は破棄します

## 必要なもの

- Claude Code（`claude` コマンド）
- PRを対象にする場合：`gh` コマンド（なければブランチの差分で代わりにします）
- Node.js 18 以上
- データの付箋でSQLを実行する場合：あなたの Claude が普段データを取れていること（psql でも Redash の MCP でも、いつものやり方のままで構いません）
- PRモードは `gh` があれば使いますが、作者の環境では GitHub につなげなかったため、ブランチ差分での代替手順でしか試していません

追加の npm パッケージは不要です。図とグラフのライブラリは同梱しています（ネット接続がなくても描画できます）。

動作を確認しているのは macOS と Linux です。Windows では試していません。

## インストール

```bash
git clone https://github.com/fkubota/understand-mode.git
cd understand-mode
bash install.sh
```

`~/.claude/skills/understand/` にコピーされます。Claude Code を開き直すと `/understand` が使えます。

### Codex でも使う（実験的）

この機能はまだフォークのブランチにあります。元のリポジトリ（fkubota/understand-mode）には含まれないので、フォークのこのブランチをチェックしてください（マージ後はフォークの main でよいです）。

```bash
git clone --branch yok-31/codex-runtime https://github.com/kinmokusei317/understand-mode.git
cd understand-mode
bash install.sh --codex
```

`~/.agents/skills/understand/` にコピーされます。Codex の会話の中で `$understand` と明示して呼びます（暗黙には起動しません）。

必要なもの：

- macOS または Linux（子プロセスをグループごと始末する POSIX の仕組みを使うため、Windows には対応していません）
- Codex CLI `codex-cli 0.171.0`（この版でだけ動作を確認しています）。`~/.local/share/understand-mode/node_modules/.bin/codex` があればそれを優先し、なければ PATH の codex を使います。版の確認は最初の質問・下書きの直前に行い、違う版ではその質問だけを断ります（サーバーの起動自体は続きます）。PATH の codex が 0.170 など別の版のとき、継承の寄り道は使えませんが、付箋の「送信先」からログイン済みCLIへの履歴なしの質問は使えます
- 親の会話が、従来のローカル記録（`$CODEX_HOME/sessions/` 以下の `rollout-...-<会話ID>.jsonl`）にあること。分割された履歴・動的ツールを持つ記録・OpenAI 以外のプロバイダの会話には対応していません
- Node.js 18 以上

認証：寄り道のCodexは、親とは別の専用の保管庫（CODEX_HOME）の中で動きます。`codex login` で ChatGPT にログインした `auth.json` を、持ち主だけが読める普通のファイルのときだけリンクで再利用します（中身は読みません。リンクや権限の緩いファイルは使いません）。APIキーやアクセストークンの環境変数は子に渡しません。ログインを確認できなければ、その質問を断ります。寄り道では、選んだ親の会話の記録を OpenAI のエンドポイントに送って回答をもらいます。その送信にあなたのログインを使うことに同意できるときだけ使ってください。

モデル：指定しなければ、このボードの新しいプロファイル（クリーンな CODEX_HOME）の既定で動きます。親の会話の設定は引き継ぎません。変えたいときはサーバー起動時に `--model <名前>` を付けます。

制約：

- 付箋のCodexは読み取り専用（read-only サンドボックス、承認要求なし）で動きます。**SQLは提案までで、実行しません**
- 親の会話の記録は、専用の保管庫に1本だけ写してから分岐します。閉じると寄り道で作った子の記録はまるごと消え、親と無関係な会話は残ります
- この機能は「読んで理解する」用途に絞っています。ツールを閉じる指定の実効性や実機での継承は、`docs/codex-port.md` の実機ゲートで確認する段階です

本筋に返す文は2通りあります。ふだんの「理解を終える」は、書いた文をそのまま返します（書き換え・要約・改行の追加はしません）。Codex では、選択メニューの「**選んだ文を返す**」でも返せます。こちらは選択した表示上の文字列をそのまま `return.md` に書きます。先頭・末尾の空白や改行、末尾の改行なしもそのままです。これはブラウザが選択として返すテキストで、main.md のバイト列そのものとは限りません（画面の文字をそのまま、が約束です）。空の文を返すときは「何も返さず閉じる」を使います（0バイトになります）。確認画面は読み取り専用で、送るのは選択時に取った文字列です。

「閉じる」が確かめるのは、ローカルの Codex CLI プロセスが終わったことだけです。プロバイダ側での課金が止まったことの証明にはなりません（課金の確認はアカウントの使用記録で）。子プロセスの停止を確かめられないときは、寄り道の記録を消さずに残したまま失敗を知らせます（無条件の後片付けはしません）。

#### サンドボックスで起動できないとき

Codex のサンドボックス（macOS の workspace-write など）の中では、ローカルにサーバーを立てる `listen` が権限不足（EPERM）で失敗することが確認されています。その場合、スキルは権限を広げず、同じユーザーのローカル端末で実行するコマンドを案内します。`CODEX_THREAD_ID` はあなたの端末では空なので、案内されるコマンドにはその会話の ID が直接書かれています。形は次のとおりです（パスと ID は案内どおりに）。

```bash
DIR=$(mktemp -d)
cp '/path/to/file.md' "$DIR/main.md"
node '/path/to/installed/understand/app/server.js' \
  --backend codex --session '<この会話のUUID>' --cwd "$PWD" --dir "$DIR" --no-open
# url.txt に出る合言葉つき URL をブラウザで開く
```

`--dir`（ボードの作業場所）は、リポジトリの外の信頼できる場所に置いてください。親の `CODEX_HOME` が標準以外なら、手動起動の端末でも同じ値を指定します。これは親記録の読取り元であり、付箋用の認証先ではありません。

## 使い方

1. Claude Code で調査や実装をしてもらう
2. わからないと思ったら `/understand`
   - やりたいことを書く：`/understand このPRを理解したい`、`/understand #128のPR`、`/understand 認証の流れを理解したい`
     → メインのClaudeが調べて、概要→変更のまとまり→必要な分だけのコード抜粋→読むときのポイント の順に説明文書を作ってから開きます
   - 図を挟む：`/understand -1 このPRを理解したい`（**本文はそのまま**、段落の合間に図とグラフが入ります）
   - 図解に寄せる：`/understand -2 このPRを理解したい`（図を主役に、本文も組み替えます）
   - 直前の回答：`/understand`
   - ファイル：`/understand src/report.py`
   - 未コミットの変更をレビュー：`/understand diff`（ブランチとの差分は `/understand diff main`）
3. ブラウザでホワイトボードが開くので、わからない箇所を選択して付箋を作る
4. 理解できたら「理解を終える」→ 返す付箋を選ぶ →「メインに送って閉じる」
5. Claude Code に戻って「終わった」と伝える。メインのClaudeが内容を受けて本筋を直します（指摘が違う場合は理由を示して押し返します）

### 操作

| 操作 | やり方 |
| --- | --- |
| 付箋を作る | 本筋や付箋の回答の文を選択 → メニュー |
| 続けて質問 | 付箋の入力欄で ⌘/Ctrl + Enter |
| 付箋を動かす | 付箋の見出しをドラッグ |
| たたむ・開く | 「たたむ」ボタン／たたんだタブをクリック。まとめて片付けたいときは上の「すべてたたむ」 |
| 付箋の大きさを変える | 右の辺で横、下の辺で縦、右下の角で両方をドラッグ（ダブルクリックで元に戻ります） |
| ボードを動かす | 背景をドラッグ、またはスクロール |
| 拡大・縮小 | ⌘/Ctrl + スクロール、または下のツールバー |
| グラフの値を質問 | グラフの点や棒をクリック |
| 本筋の文を推敲 | 本筋カードの「Tsuzuriで推敲」 |

### 本筋を推敲する（Tsuzuriノート）

本筋カードの右上にある「Tsuzuriで推敲」を押すと、本筋のMarkdownを写したノートが開きます。
ここで直しても元の本筋・付箋・返す文は変わりません（推敲した文を使うには、「Markdownを書き出す」か、内容を写してメインに伝えてください）。

- 「書く」で直し、「読む」で読みやすい表示を確認、「語の候補」で [tsuzuri](https://github.com/MaryCache/tsuzuri) 同梱の校正辞書に当たる語を一覧します（候補を押すとその場所を選ぶだけ。自動では置き換えません）
- 文を選択して「選んだ部分を推敲してもらう」を押すと、その抜粋と「読み手への希望」だけをAIに送り、提案を表示します。「この提案に替える」を押したときだけ、その範囲が置き換わります（待っているあいだに原稿を直した場合は、ずれるので当てずに止まります）
- 下書きはそのタブの中だけに保存されます。メインに返して閉じると、ほかの付箋と同じく捨てます
- 採用した提案や手直しは「履歴」で見返し、[修正履歴をJSONで書き出す](docs/revisions.md)ことができます。
- Codexで別に作った図は、[「ローカルの図」から追加](docs/local-images.md)してノートに表示できます。ノートが画像を生成したり、AIに送ったりすることはありません。

付箋の質問先を確かめたいときは、[インストールしたアプリでのCLI確認手順](docs/installed-cli-test.md)を参照してください。既定のテストは偽のCLIを使い、実際のログインは不要です。

### 付箋の送信先を切り替える（履歴なしの質問）

付箋の「送信先」メニューから、そのマシンにログイン済みのCLI（Codex / Claude）へ直接質問を送れます。メインや付箋の会話は渡さず、付箋の引用と質問文だけを送るので、別のモデルの意見を履歴なしで取れます。

- 使えるのは、ローカルのCLIに ChatGPT（codex）または claude.ai（claude）でログインしているときだけです。モデルは Codex が `gpt-6.2-terra` / `gpt-6.2-astra`、Claude が `haiku` / `sonnet` / `opus` です
- 呼び出しは記録を残さず、道具・MCP・設定ファイルを全部閉じた状態で行います（Codex は `exec --ephemeral`、Claude は `--safe-mode --setting-sources ''` など）。APIキーや独自エンドポイントは渡しません
- Codex は `auth.json` を使います（持ち主だけが読める普通のファイルのときだけリンクで再利用します。キーチェーンだけのログインには対応していません）。Claude はいつもの `~/.claude` または `CLAUDE_CONFIG_DIR` のログインをそのまま使います
- 送信のたびに実際のAIを呼ぶので、普段どおり費用がかかり得ます

これは推敲のための小さなノートであって、tsuzuri 本体（執筆意図・文機能の記録や閲覧アプリ）ではありません。
推敲は抜粋と希望だけを、tsuzuri 同梱の「執筆意図の質の確認」といっしょに別の呼び出しへ渡します。メインや付箋の会話には載りませんが、AI を呼ぶので普段どおり費用がかかり得ます。Claude では道具と外部連携を全部閉じて記録に残さず呼び、Codex では記録に残らない下書きとして呼びます。
「語の候補」に使う正規表現には後読みを含むものがあり、対応していないブラウザではその語は出ません（推敲自体は使えます）。

設定ファイルはありません。モデルも道具もSQLの書き方も、分身がメインのセッションから引き継ぎます。

変えられるのは待ち時間だけです。重い調べものに時間がかかるようなら、`UNDERSTAND_TIMEOUT_SEC=600` のように環境変数で伸ばせます（既定は300秒）。

## しくみ

- 質問のたびに `claude -p --resume <メインのセッション> --fork-session` を実行します。メインの文脈を引き継いだ分身が答えるので、メインの会話は汚れません
- 付箋の続きの質問はその付箋のセッションに、子付箋は親の付箋のセッションから分岐します
- 閉じると、このアプリが作った分岐セッションの記録（`~/.claude/projects/` の該当ファイル）だけを削除します。メインのセッションには触れません

## 注意

- 質問1回ごとに、メインの会話全体を読み込みます。会話が長いと費用がかかります（2回目以降はキャッシュが効きます）
- 分身はメインと同じモデルのまま、思考量（effort）だけ `low` で動きます。寄り道を軽く回すためです
- グラフの値は、Claudeが取得して返した結果の表から描いています。アプリがデータベースに直接つないでいるわけではありません
- このアプリは接続先も道具も持ちません。承認のときに「いつものやり方で実行して」と頼むだけです。トンネルや認証の用意は、普段どおり先に済ませておいてください
- 実行できるのは `select`（または `with`）で始まる1文だけです。書き込みや複数文はアプリ側で弾きます
- 実行できる範囲は、あなたが普段 Claude Code に与えている許可のままです。アプリが許可を足すことはありません
- 承認を挟むかどうかも、メインのセッションの権限モードに合わせます。アプリが独自に厳しくすることはありません
- 承認前の実行を止めているのは `Bash` とファイル編集の禁止です。psql や bq のようなコマンド系は止まりますが、**MCPの道具は名前が分からないので止めきれません**。MCP経由でデータを取っている方はご注意ください
- アプリのURLには合言葉が入っています。この合言葉がないと操作できないので、**URLを人に見せないでください**。同じマシンの別のページやプロセスからの操作を、これで防いでいます
- 付箋の内容は、ブラウザのタブを閉じるまでそのタブの中だけに保存されます

```bash
rm -rf ~/.claude/skills/understand
```

## 開発する人へ

続きの開発は `CLAUDE.md` と `docs/architecture.md` から読んでください。`npm run mock` で、費用をかけずに画面を動かせます。

```bash
npm run mock       # 偽の claude で起動（費用ゼロ）
npm run test:sql   # SQL実行まわりの確認（ClaudeもDBも使わない）
npm i && npm run test:e2e   # mock を動かしたまま、画面を一通り自動操作
```

デモのGIFは `docs/media/demo.gif` です。差し替えるときは同じパスに置いてください。
